Form analysis

1. Issues in the original form

<form action="/submit" method="GET">
<input type="text" name="username">
<input type="password" name="password">
<button type="button">Login</button>
</form>
  • type="button" does not submit the form.
  • method="GET" puts the password in the URL.
  • No labels, required or autocomplete.
  • No HTTPS, CSRF protection or rate limiting.

2. Why the request is not triggered

A type="button" button has no default action. The browser sends a request only when a submit event fires, which happens for type="submit". Without JavaScript, clicking Login does nothing.

3. Role of GET

GET sends data in the URL query string, so a submit would look like this:

GET /submit?username=student&password=Simats%402026 HTTP/1.1

The password would show in the address bar, history, server logs and the Referer header. GET is for safe reads such as search, not for credentials.

4. Corrected implementation

<form action="/submit" method="POST">
  <label for="username">Username</label>
  <input type="text" id="username" name="username"
         autocomplete="username" required>

  <label for="password">Password</label>
  <input type="password" id="password" name="password"
         autocomplete="current-password" required minlength="8">

  <button type="submit">Log in</button>
</form>

5. Secure data transmission

HTTPS (TLS)Encrypts data in transit.
