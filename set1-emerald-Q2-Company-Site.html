Compatibility report

1. Original code and its problems

<html>
<head>
<title>Company</title>
</head>
<body>
<div>
<h1>Welcome
<p>About us
</div>
</body>
</html>
  • <h1> and <p> are never closed, so the paragraph ends up inside the heading.
  • No DOCTYPE, so browsers may use quirks mode.
  • No lang, charset or viewport meta tag.

2. How browsers interpret it

Browsers repair bad HTML, but each engine repairs it a little differently. Quirks mode changes the box model and default font sizes. Unclosed tags can change where margins and headings end. With no CSS reset, each browser also applies its own default margins and fonts. The result is an inconsistent layout.

3. Missing semantic elements

Only <div> is used. The page needs <header>, <nav>, <main>, <section> and <footer>.

4. Corrected W3C-compliant HTML

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Company</title>
</head>
<body>
  <header>
    <h1>Welcome</h1>
  </header>
  <main>
    <section>
      <h2>About us</h2>
      <p>We build dependable software.</p>
    </section>
  </main>
  <footer>
    <p>&copy; 2026 Company</p>
  </footer>
</body>
</html>

5. Cross-browser techniques

  1. Validate with the W3C Markup Validator.
  2. Always declare <!DOCTYPE html>.
  3. Use a CSS reset and box-sizing: border-box.
  4. Use vendor prefixes (Autoprefixer) and fallbacks with @supports.
  5. Use relative units and media queries.
  6. Test in Chrome, Firefox, Safari, Edge and on real phones.
  7. Check caniuse.com before using a new feature.
