HTTP request and response

Missing semantic elements (Q1.1)

The original form has no <header>, <nav>, <main>, <section>, <footer>, <fieldset> or <label>. This site adds them.

Request (Q1.3)

POST /register HTTP/1.1
Host: symposium.example.edu
Content-Type: application/x-www-form-urlencoded
Content-Length: 41

name=Priya+Raman&email=priya%40college.edu

POST sends the data in the body. The headers tell the server the content type and size.

Response cycle (Q1.4)

  1. The user clicks Submit and the browser builds the request.
  2. The browser opens a connection (DNS lookup, TCP, TLS) and sends it.
  3. The server reads the form data, validates it and saves the registration.
  4. The server sends a response with a status line, headers and a body.
  5. The browser reads the status and renders the confirmation page.
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8

<h1>Registration received</h1>

Usability and accessibility (Q1.5)

  • Add labels to every input and use correct input types.
  • Add required, autocomplete and clear error messages.
  • Show a confirmation message after submitting.
  • Keep keyboard focus visible and use good colour contrast.
  • Use a responsive layout and HTTPS.
